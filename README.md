# TriageDesk

**A support desk where every ticket is auto-triaged on arrival — category, priority and a draft reply — before a human ever sees it.**

Full-stack, from the database schema to the browser: FastAPI + SQLAlchemy + JWT auth + RBAC on the backend; Vue 3 + TypeScript + Pinia + Vite on the frontend. Designed to run offline with zero external services, with an optional LLM upgrade path.

> Screenshots: see `docs/` (dashboard with SLA breach table, ticket detail with the AI triage card, conversation timeline).

## Why this exists

Most "AI features" fail at the integration seam: a model notebook nobody productionizes, or a CRUD app with an AI bolt-on that nobody trusts. TriageDesk demonstrates the full path:

1. A customer submits a ticket with **no category and no priority**.
2. On submit, the backend runs **AI triage**: a multinomial Naive Bayes classifier (pure Python, no sklearn) predicts the category with a confidence score; keyword rules set the priority; a reply is drafted.
3. Agents see the triage card, can adopt the draft reply with one click, and move tickets through a **guarded state machine** (`open → in_progress → resolved → closed`; illegal transitions are rejected with 422).
4. **SLA tracking** per priority (1h urgent → 72h low) with breach detection surfaced on the dashboard.

## Features

**Backend (FastAPI + SQLAlchemy)**
- JWT auth with access/refresh tokens, PBKDF2 password hashing (stdlib, no bcrypt)
- Role-based access control (`admin` / `agent` / `customer`) via route-level dependency guards
- Ticket state machine with legal-transition validation
- Comment timeline with **internal notes** (agents see them; customers never do)
- Paginated, filtered, searchable ticket listing
- SLA service: first-response tracking + breach detection
- Dashboard aggregates: counts, category distribution, 7-day trend, median first response, breach list
- Self-serve signup is customer-only — staff accounts are provisioned, preventing trivial privilege escalation

**Frontend (Vue 3 + TypeScript + Pinia)**
- Login/register with demo-account shortcuts
- Ticket list with status/priority/category filters and text search
- Ticket detail: conversation timeline, AI triage card, "Use as draft", workflow buttons
- Agent/admin dashboard with Chart.js trend and SLA breach table
- Router guards, automatic token refresh on 401, typed API client

## The AI triage, honestly evaluated

The classifier is a bigram-augmented multinomial Naive Bayes trained on ~200 synthetic tickets (5 categories). The evaluation below is on **30 tickets with entirely different phrasings** — no shared sentence stems with training data — so it measures generalisation, not template recall:

```
triage accuracy on unseen wording: 26/30 = 86.7%
  account   6/6
  billing   6/6
  bug       4/6
  feature   4/6
  general   6/6
```

Confidence scores are per-token-normalised so they don't saturate at 1.00 on long inputs — e.g. *"My card was charged twice"* → `billing` at 0.73; *"The app crashes when I open reports"* → `bug` at 0.31 (low confidence is shown, not hidden — a triage UI that always says 99% is lying to its users).

**Upgrade path:** set `OPENAI_API_KEY` and triage switches from the local classifier to an LLM (same interface, richer replies). The classifier stays as the offline fallback and as a cost-control baseline.

## API surface (abridged)

```
POST /api/auth/register        customer signup (staff roles are provisioned only)
POST /api/auth/login           → { access_token, refresh_token, user }
POST /api/auth/refresh
GET  /api/tickets              ?status=&priority=&category=&q=&page=   (role-scoped)
POST /api/tickets              auto-triage on create
GET  /api/tickets/:id
POST /api/tickets/:id/status   state machine guarded (422 on illegal transition)
POST /api/tickets/:id/assign   admin-only
GET/POST /api/tickets/:id/comments   internal notes filtered by role
GET  /api/dashboard            agents/admins only
GET  /api/health
```

Interactive docs at `/docs` (Swagger UI, generated by FastAPI).

## Run it

```bash
make setup     # pip install + npm install
make seed      # 5 users, 12 tickets across the funnel
make api       # backend on :8123
make web       # frontend on :5173
```

Demo accounts: `agent@demo.dev` / `agent-demo-1234`, `admin@demo.dev` / `admin-demo-1234`, `customer1@demo.dev` / `customer-demo-1234`.

Or with Docker: `docker compose up --build`.

```bash
make test
```

## Stack decisions

- **SQLite by default** — zero-config demo; models are plain SQLAlchemy and switch to Postgres via `TRIAGEDESK_DB`.
- **Pure-Python classifier instead of sklearn** — keeps the repo installable anywhere in seconds; on a 5-class short-text problem, NB is an honest, explainable baseline. The `Triage` interface is a strategy pattern, so the LLM upgrade doesn't touch the API layer.
- **No WebSocket** — polling + refresh tokens is enough at this scale; real-time would be the first thing to add for a client who needs it, not before.
